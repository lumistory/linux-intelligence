# zsh: add-zsh-hook replaces an already-defined function

Generated by hand from a pty session while fixing the zsh adapter; the raw
terminal transcript is `results/t01.zsh.term.log` (pre-fix) and
`results/t01.zsh.events.jsonl` (post-fix).

## What add-zsh-hook does

It appends the *name* to `precmd_functions`/`preexec_functions` **and** runs
`autoload -- <name>`. When `<name>` is already a defined function, `autoload`
marks it as an autoload stub, which discards the body.

## Observed

With `add-zsh-hook precmd _li_precmd` (first zsh adapter):

    zsh: command not found: _li_now
    (no hook events at all)

After the fix (append directly to `precmd_functions`):

    {"type":"CommandFinished","payload":{"command":"echo hello-zsh",
     "exit_status":0,...}}

## Conclusion

Do not call `add-zsh-hook` with the name of a function you have already defined.
Append to the `*_functions` arrays instead -- that is the whole of what
`add-zsh-hook` does, minus the destructive autoload. The adapter keeps the
arrays de-duplicated by hand so re-sourcing stays idempotent.
